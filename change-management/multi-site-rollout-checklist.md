# Multi-Site / Multi-Country Rollout Checklist

For rolling out a new payment method, POS update, loyalty integration or back-office change across many stores or several countries.

## 1. Requirements and readiness

- [ ] Business requirements agreed and signed off with the country or business owner
- [ ] Local requirements checked: currency, tax, receipt format, language, local payment rules
- [ ] Integration partners (banks, payment or loyalty providers) ready and their test environment available
- [ ] Store hardware and software versions meet the minimum requirements
- [ ] Support documentation and FAQ ready for the service desk and stores

## 2. Testing

- [ ] Functional tests in a test environment, including failure cases (timeouts, declines, refunds)
- [ ] End-to-end test with the integration partner
- [ ] Test on every hardware / firmware combination in use
- [ ] Rollback tested

## 3. Pilot

- [ ] Pilot in one or two stores with engaged store managers
- [ ] Hypercare: on-site or close remote support during the first days
- [ ] Daily check of transactions, errors and store feedback
- [ ] Go / no-go meeting before the wider rollout

## 4. Rollout in waves

| Wave | Scope | Go / no-go criteria |
|---|---|---|
| 1 | Pilot stores | No blocking issues for an agreed number of trading days |
| 2 | One region or a small share of stores | Error rate within target; support tickets under control |
| 3+ | Remaining stores / countries | Same criteria |

- Avoid peak trading days (weekends before holidays, campaign days)
- Schedule deployments outside opening hours across time zones

## 5. Hypercare and handover

- [ ] Extra monitoring and a dedicated support channel for the first weeks
- [ ] Known issues list kept up to date
- [ ] Handover to normal support with runbooks and contacts
- [ ] Lessons learned recorded
